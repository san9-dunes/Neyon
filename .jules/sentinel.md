## 2025-02-20 - Migrate App Password from MD5 to PBKDF2
**Vulnerability:** The application used MD5, a cryptographically broken hashing algorithm, to store the application unlock password. This makes the stored hash vulnerable to collision attacks and extremely fast offline brute-forcing if an attacker gains access to the local storage preferences.
**Learning:** Due to backwards compatibility concerns and avoiding breaking existing users, the verification logic must first detect the hash format (e.g., checking if it starts with a specific prefix like "PBKDF2$") before verifying. An inline migration approach works best here, where a successful unlock with the old MD5 hash automatically upgrades and overwrites the stored value with the new secure PBKDF2 hash.
**Prevention:** Always use secure, modern hashing algorithms like PBKDF2, Argon2, or bcrypt for passwords instead of MD5. Ensure that when migrating hashing algorithms, an iterative/lazy migration is implemented so existing user data remains accessible without forcing manual password resets.
